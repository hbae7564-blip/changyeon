# 카카오 오픈빌더 스킬 서버 개발

`changyeon-kakao-bot`은 Express 기반 스킬 서버로, 오픈빌더의 "예약접수" 블록 전체를 `/skill/validate` 엔드포인트 하나가 처리한다. 수정 전 반드시 아래 제약을 숙지한다.

## 절대 지켜야 할 제약 (위반 시 실서비스 장애로 이어짐)

1. **5초 응답 제한**: 카카오는 5초 안에 응답을 못 받으면 요청을 실패 처리하고 고객 화면에 아무것도 뜨지 않는다. Slack/카카오 API 호출처럼 시간이 걸릴 수 있는 작업은 `notifyCounselor(...).catch(...)` 형태로 **await 없이** 실행하고, 그 즉시 `sendKakaoResponse`로 고객 응답을 먼저 내려보낸다. 새 기능에서 외부 API를 호출할 때도 이 패턴을 그대로 따른다.
2. **블록 통합 유지**: 예약날짜/성함/전화번호/문의내용~입력완료~다시입력하기~처음부터다시입력하기가 모두 `/skill/validate` 하나에 몰려 있는 이유는, 블록을 나눴을 때 오픈빌더 파라미터가 유실되는 버그를 겪었기 때문이다(코드 상단 주석). 새 발화 케이스를 추가할 땐 새 블록을 만들지 말고 이 안에 갈래를 추가하는 것을 우선 검토한다.
3. **리셋 스냅샷(`pendingResetSnapshot`)**: "다시입력하기" 발화가 남아있는 상태로 사용자가 이미 새 값을 다 입력해도 같은 발화가 다시 오는 오픈빌더 특성 때문에 존재하는 안전장치다. 리셋 관련 버그를 고칠 땐 이 스냅샷 비교 로직부터 확인한다.

## 입력값 검증 로직 수정

- `isBlank`, `isGibberish`, `isValidPhone` 세 함수가 검증의 핵심이다. 새 오류 케이스를 추가하면 반드시:
  1. 함수에 케이스 추가
  2. `SCENARIO.md`의 해당 설명 갱신
  3. README의 "테스트해봤을 때" 목록에 새 케이스 추가 여부 확인
- 전화번호 검증은 "문장 속에 자연스럽게 포함된 번호는 통과, 숫자/영문자가 바로 붙은 경우만 오류"라는 미묘한 규칙이다 (`isValidPhone`의 앞뒤 문자 검사). 정규식만 보고 성급히 단순화하지 않는다.

## 상담원 알림 로직

- `notifyCounselor`는 `SLACK_WEBHOOK_URL` → `KAKAO_REFRESH_TOKEN` → 콘솔 로그 순으로 폴백한다
- 새 알림 채널(SMS 등)을 추가할 땐 이 함수의 분기만 늘리고, 호출부(`/skill/validate` 안의 fire-and-forget 호출)는 건드리지 않는다
- 카카오톡 "나에게 보내기"는 액세스 토큰이 만료되면 리프레시 토큰으로 자동 갱신되며, 카카오가 새 리프레시 토큰을 내려주면 콘솔에 로그로 남는다 — 이 경우 Render 환경변수 `KAKAO_REFRESH_TOKEN`을 사용자가 직접 갱신해야 한다고 안내한다 (Claude가 직접 Render 대시보드에 입력하지 않는다)

## 로컬 테스트 방법

```bash
npm install
npm start
```
`http://localhost:3000`에서 "정상적으로 실행 중입니다"가 뜨면 성공. `/skill/validate` 테스트는 오픈빌더 요청 형식을 흉내 낸 JSON을 POST한다:

```json
{
  "userRequest": { "utterance": "다 입력했어요", "user": { "id": "test-user" } },
  "action": { "params": { "예약날짜": "1/1", "예약자성함": "홍길동", "전화번호": "010-1234-5678", "문의내용": "사업운" } }
}
```

회귀 테스트 시 반드시 확인할 5가지 케이스 (README 기준):
1. 정상 입력 → 요약 메시지 + "다시입력하기" 버튼
2. 전화번호 형식 오류 (`01012345678a`) → 오류 메시지
3. 의미 없는 문자만 입력 (`ㅁㄴㅇㄹ`, `!!!`) → 오류 메시지
4. 문장 속 정상 전화번호 (`"번호는 010-2222-3333이에요"`) → 정상 통과
5. 리셋 발화("처음부터 다시입력하기") → 파라미터 초기화 응답

## SCENARIO.md 동기화 원칙

고정된 질문/응답 문구(웰컴, 슬롯 질문, 가격 안내 등)는 `SCENARIO.md`에, 판단이 필요한 로직은 `server.js`에 있다. 문구를 바꾸는 요청은 `SCENARIO.md`만 수정하고 코드는 건드리지 않는다 — 반대로 로직 변경 요청에서 문구도 바뀐다면 두 파일을 함께 갱신한다.
